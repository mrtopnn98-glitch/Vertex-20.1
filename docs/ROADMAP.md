# Roadmap

Планы развития Vertex. Порядок — по приоритету.

## 1. TAS-модуль (главное направление)

### Для чего нужен

TAS (Tool-Assisted Speedrun) — модуль записи и воспроизведения инпута с покадровой точностью. Применения:

- **Идеальные забеги**: записанный однажды набор входных кадров воспроизводится без единого отклонения — гарантированный повтор трюка.
- **Оффлайн-тест avoid-траекторий**: прогон симуляции без участия игрока, сравнение вариантов прохождения.
- **Поиск оптимальной траектории**: перебор веток поведения на копии мира (та же инфраструктура, что у Blatant-авойда, но с возвратом к снапшоту).
- **Разбор ошибок**: откат к любому тику и переигровка момента.

### Как будет работать

```
[ЗАПИСЬ]                [САВСТЕЙТЫ]              [ПОИСК]
инпут каждого тика  →   memcpy-снимок мира    →   BFS/DFS по виртуальным
пишется в кольцевой     в любой тик               тикам с хэш-дедупом
буфер (50 кадров/с)     состояний
```

1. **Детерминизм.** Симуляция должна быть воспроизводимой: RNG фиксируется сидом, все внешние события (пакеты сервера) логируются вместе с тиком получения.
2. **Буфер инпута.** На каждый тик сохраняется структура `CNetObj_PlayerInput` (направление, джамп, хук, файр, таргет-углы). Кольцевой буфер на последние N тиков + дамп в файл.
3. **Савстейты.** Снимок мира (та же копия, что строит Blatant-авойд, расширенная до полного состояния) сериализуется побайтово. Загрузка снапшота откатывает мир к тику.
4. **Хэш состояния.** FNV-1a по ключевым полям снапшота — быстрое сравнение веток при поиске: если состояние уже посещалось, ветка отсекается.
5. **Поиск траектории.** Итеративное углубление по виртуальным тикам: пробуем `{влево, вправо, нейтрально, джамп, хук}` на каждом развиле, оцениваем дистанцию до цели, лучшую ветку фиксируем в буфер инпута.

### C++-инфраструктура

| Механизм | Где применяется |
|---|---|
| `std::vector<CNetObj_PlayerInput>` / `std::deque` | буфер инпута, кольцевой буфер |
| `std::unordered_map<uint64_t, Snapshot>` + FNV-1a | хэш-таблица посещённых состояний |
| Побайтовая сериализация (`memcpy`-снимки + `fwrite`/`fread`) | савстейты, дампы реплеев |
| Фиксированный шаг 50 тиков/с | синхронизация записи и воспроизведения |
| Лямбда-предикаты для оценки веток | функция стоимости в поиске траектории |
| `std::chrono`-метки только для UI | детерминизм ядра от реального времени не зависит |

### Этапы

- [ ] v0.1 — запись инпута в файл + воспроизведение
- [ ] v0.2 — савстейты (сохранить/загрузить состояние мира)
- [ ] v0.3 — откат на N тиков в реальной игре
- [ ] v0.4 — поиск траектории на симуляции с хэш-дедупом
- [ ] v0.5 — интеграция с avoid-движком (автотест режимов)

## 2. Унификация движков

Полное слияние legacy `VxAf*` и KRX-glue `Avoid*`: один движок, один набор конфигов, миграция настроек. После унификации VxAf-конфиги объявляются устаревшими и удаляются.

## 3. HUD-меню

- Профили настроек (сохранение/загрузка пресетов Basic/Blatant).
- Индикатор состояния авойда на игровом экране (активен/агент/предикты в секунду).
- Горячие клавиши быстрого переключения агентов.

## 4. Прочее

- Статистика срабатываний: сколько раз за раунд сработали инверсия, автохук, unfreeze.
- Отладочный оверлей для симуляции (подсветка опасных тиков при `AvoidDebug 1`).
